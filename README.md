# CyberHealth（摸鱼养生局）

Intelligent Micro-Break Companion · **Small Moves, Lasting Habits.**

沿用现有 Next.js / React / TypeScript 项目的 Web/PWA。无需注册，用当前场景、可用时间、活动空间与个人关注部位筛选微动作；按用户设置在网页运行时提醒，用户确认完成后才更新真实成长记录。

## 本地运行与验证

Node.js 20.19+（22.x 请使用 22.13+；推荐当前 LTS），依赖由 `package-lock.json` 锁定：

```sh
npm ci
npm run dev
# http://127.0.0.1:4173

npm test
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E 会自动启动生产服务器，运行前先 `npm run build` 并关闭占用 4173 的其他服务器。桌面 1440×1000 与手机 390×844 两个项目都使用隔离 Chromium；手机项目为视口/触控模拟，不等于 iOS 真机验证。可通过 `PLAYWRIGHT_BROWSERS_PATH` 指向已安装的专用浏览器目录。开发模式不注册 Service Worker，以免缓存 HMR；离线测试与安装预览使用 `npm run build && npm run start`。

## 页面与流程

- **首页**：主要提醒状态、下次计划、频率与暂停/关闭/修改；当前场景、时间与空间；立即活动；今日真实次数与时长；次级节气/每日元气签与花园预览。
- **活动**：确认条件、查看推荐原因、换一个或排除不适合动作；详情显示来源、分步骤与安全提示。开始、暂停、继续、跳过，计时结束只进入待确认状态。明确确认后记录一次。
- **花园**：主导航入口。未配置时明确标为本地演示；P1 云服务启用后要求正式账号。
- **成长**：今日完成、近七日与四周趋势、场景次数、提醒处理比例、花园贡献、累计时长、常用动作与历史。只统计用户确认，时长是动作建议时长之和，不是传感器测量。
- **我的**：重开偏好引导、修改全部提醒规则、系统通知授权、已排除动作恢复、JSON 导出及需确认的本地数据清除。账号与手动云同步预览、智能调整开关/原因/重置/历史。灵宠收藏、主题预览保留次级入口。
- **首次引导**：欢迎 → 关注部位 → 常用场景 → 提醒偏好 → 通知授权。可随时跳过，拒绝通知不阻塞站内使用。

## 架构与数据

| 层 | 文件 / 作用 |
|---|---|
| UI | `src/components/App.tsx` 与 Onboarding/TeachingCard/ReminderFields |
| 动作内容 | `activities.ts`、`microActivities.ts`、`sourceCheckedActivities.ts`、独立 `evidenceSources.ts` |
| 推荐 | `recommend.ts` 纯函数：审核/场景/时长/姿势/器械/用户排除硬过滤；35/25/20/20 评分后做近期多样性调整 |
| 执行与成长 | `execution.ts`、`growth.ts`，时间参数可注入、唯一 session ID 防重复奖励 |
| 提醒 | `reminders.ts` 规则、`notifications.ts` 能力与展示、`data/reminderClaim.ts` 标签协调 |
| Repository | `src/data/repository.ts` 同步本地适配器，账号隔离本地空间 + 可选 Supabase 云适配器 |
| PWA / 文化 | manifest、`public/sw.js`、原创 PNG 图标；`seasonal.ts` 日期表 |
| 花园 | 保留 `garden.ts` 演示与 `gardenRemote.ts`；P1 新增正式账号与 002/003 迁移草案，未远程执行 |

游客核心数据沿用 localStorage 键 `moyu-wellness-v1`，schema 已升级为 **v4**（新增学习、推荐曝光、文化偏好与每日签），迁移保留 v1/v2/v3 偏好、记录、反馈、元气与花园数据。Repository 封装读取、迁移、保存、订阅、导出与清除，便于未来切换 IndexedDB/Supabase。localStorage 是为兼容原架构选择的等效持久化方案；每个标签页修改前读取最新数据，其他标签订阅 storage 事件，不会把旧快照在渲染后写回。

IndexedDB 单独保存提醒 occurrence claim，读写事务跨标签串行化，只有一个标签能展示同一次提醒。存储失败会明确提示；无法协调标签时关闭自动提醒，仍可主动活动。数据清除仅清除本应用游客数据与提醒 claim，不退出或删除 Supabase 账号/远程花园。隐私窗口、清除站点数据或更换设备会丢失游客数据，请先导出。

## 提醒能力边界

- 用户主动开启，可随时关闭，暂停到所选时刻，到期恢复；每日上限默认 3 次、最小间隔默认 60 分钟。
- 工作时段与免打扰支持跨午夜；工作起止相同表示全天，DND 起止相同表示不设置。完全被 DND 覆盖时显示暂无可用时段。
- 延后 15/30/60 分钟复用同一次提醒，不另占每日额度，但依然遵守工作和 DND 时段；普通提醒遵守最小间隔。
- 延后、跳过、暂停、接受、已活动均记录事件、时间、场景与原因，用于可解释的有限自适应。「已活动」不虚增完成或元气。
- 只在可见前台页面展示到期提醒，计时中、暂停动作或待完成确认时不发普通提醒。后台节流、设备休眠、关闭网页后不能保证触发。重新打开会按规则检查，忽略期间不累发多条。
- 浏览器通知必须用户点击授权。拒绝/不支持/非安全上下文明确降级；iPhone/iPad 提示从 Safari 添加主屏幕后打开，Android/桌面可使用浏览器安装菜单。PWA 安装或通知授权都**不代表已经实现后台 Web Push**。
- 本轮未新增推送订阅、服务端排程或生产基础设施。后续要实现关闭网页后的推送，需独立确认服务端存储、调度、VAPID 密钥与部署方案。

## 动作审核与来源

12 张动作卡已核对机构公开资料，覆盖 L1 安静微动作、L2 轻活动、L3 步行等较完整活动。需要支撑的动作必须先明确确认稳固无轮椅或可扶墙面。旧 12 项演示内容及未审核计划保留，但不参与自动推荐。硬性条件不满足时展示空状态。

**source-checked 代表机构资料与动作方向已核对，不能理解为医学专业审校或临床验证。** 微休息计时是产品设计，不能推导治疗效果。内容正式运营前仍需专业人员审校个人适用范围、剂量与措辞；暂无核对过的示范动画，沿用清晰文字步骤。

来源为 [NHS 坐姿动作](https://www.nhs.uk/live-well/exercise/sitting-exercises/)、[柔韧动作](https://www.nhs.uk/live-well/exercise/flexibility-exercises/)、[力量动作](https://www.nhs.uk/live-well/exercise/strength-exercises/)、[平衡动作](https://www.nhs.uk/live-well/exercise/balance-exercises/)、[步行](https://www.nhs.uk/live-well/exercise/walking-for-health/)和原有 NHS 肩颈资料；具体支持范围见 `evidenceSources.ts`。不复制机构图文或视频、不声称治疗疾病。

节气使用香港天文台 [2025](https://www.hko.gov.hk/en/gts/time/calendar/text/files/T2025e.txt)、[2026](https://www.hko.gov.hk/en/gts/time/calendar/text/files/T2026e.txt)、[2027](https://www.hko.gov.hk/en/gts/time/calendar/text/files/T2027e.txt) 逐年对照资料，按北京时间日期切换，非精确交节时刻；超出收录范围明确降级。24 节气与每日签均为结构化双语内容；每日抽签结果本地保存，同一天不重抽，不影响微活动硬性条件。

## P1 个性化与账号

智能调整默认关闭。近 28 天内，同一 2 小时时段至少 6 次有效反馈、跨 3 天才学该时段；接受率至少 2/3 时在未来 30 分钟内优先，延后比例至少 2/3 时尝试推迟 15 分钟；有效记录至少 6 条且最近连续跳过 4 次，最小间隔最多增加 30 分钟或原间隔一半。总调整最多推迟 30 分钟，不增加每日上限、不突破工作/DND、不打断执行，关闭与重置立即恢复显式规则。计划时间、实际触发、前台展示与系统 API 状态分开保存，系统通知送达始终标为未知。

动作新增喜欢、太简单、太难、场景不适合、不再推荐、无特别感觉六类可选反馈。保留硬过滤与 35/25/20/20 评分；显式喜好/难度影响软分，最近 8 次推荐曝光降低重复。重新启用动作会写入独立恢复事件，跨设备合并后不会被旧排除覆盖。

账号采用自愿邮箱 OTP，保留已有 Supabase 客户端；游客使用无需登录。P1 功能需 `NEXT_PUBLIC_P1_CLOUD_ENABLED=true` 且测试迁移完成。每个账号在本机独立存储，退出恢复游客；云同步先预览再选择，事件保留原 ID 去重，偏好版本冲突拒绝覆盖。当前为用户发起的手动同步，不是完整自动后台同步。游客原记录、正在运行的计时和设备通知权限不会被自动上传或搬走。

正式花园最多两人，每日最多 5 份露水（北京时间日界），只接受与私有云端完成事件匹配的活动，服务端做时间与内容白名单检查；这不证明实际身体活动。私有奖励账本防跨花园重复，好友只能读贡献摘要。邀请链接随机 token、7 天有效，至少间隔 60 秒、每日最多 10 条；60 秒休息邀请 10 分钟内回应，至少间隔 30 分钟、每日最多 3 次。用户退出撤销旧链接并转移维护者，剩余成员保留植物成长。界面每 15 秒同步花园，未接入 Realtime。

**当前无 Supabase 测试项目配置，真实邮箱投递、跨设备与两真实账号花园验收尚未执行。** SQL 草案只在嵌入式 PostgreSQL 测试，不能据此声称正式联网验收完成。具体步骤与双人演示见 [测试项目配置指南](docs/SUPABASE_SETUP.md)。

## 本地演示与旧版本兼容

未配置后端时，花园明确显示「本地演示模式」，邀请只能在同一浏览器内使用，不是跨设备好友。演示与游客数据继续保留在本地，已有灵宠、主题入口也保留。

P0 已有的匿名 Supabase 接入继续作为兼容路径；新 P1 测试环境应按 [配置指南](docs/SUPABASE_SETUP.md) 审阅并确认 001 → 002 → 003 迁移，不要只运行旧 001 后声称 P1 权限与奖励规则生效。003 保留既有匿名成员身份和贡献，但之后花园写操作要求关联邮箱成为正式账号。应用不会代你执行迁移。

个人历史由本人提交确认，服务端只校验事件、成员、唯一键、额度及时间条件，无法验证真实身体活动。好友不能查看 personal_events；花园快照只暴露成员昵称、共同贡献摘要和休息邀请状态。本地清除只作用于当前账号或游客空间，不删除云端账号或花园。
