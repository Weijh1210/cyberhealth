# 摸鱼养生局

一个以学习、工作陪伴为主流程的轻休息 Web MVP。项目沿用原有 Next.js App Router、活动库、推荐、计时、灵宠、元气和文化主题，并在此基础上增加首次引导、陪伴 session、提醒事件和双人异步花园。

## 本地运行

需要 Node.js 20.9+。依赖由 `package-lock.json` 锁定。

```bash
npm install
npm run dev
```

打开 http://127.0.0.1:4173/。检查与生产预览：

```bash
npm run typecheck
npm test
npm run build
npm run start
```

## 主流程

首次引导可跳过，可从设置重新编辑。用户选择常见场景、关注部位、静音和动作幅度偏好、行动条件，以及提醒时段和间隔。这些是偏好，不是诊断。首页优先展示节气主题、今日颜色、娱乐性质的元气签、灵宠与陪伴状态、共同花园和当前适合的活动。

开启陪伴时沿用上次设置，并能直接修改当前场景、可用时间和行动条件。提醒仅在页面运行期间按设定时间出现，可开始推荐活动、换一个、延后或暂停。活动由用户自行计时和确认；有疼痛或不适时可跳过。应用不检测久坐、不测量运动量、不声称改善健康。Color Walk 只有在时间、场景和行动条件允许外出时才推荐；节气和颜色只影响主题与排序，不能覆盖硬性限制。

个人灵宠按用户确认完成的活动获得元气和收藏。重复确认同一 activity session 不会重复领奖，刷新后仍保留已完成状态。中断使用不会扣分。

## 双人花园：演示与真实同步

不配置 Supabase 时，首页明确显示“本地演示模式”。可在**同一浏览器**中创建花园、生成链接、切换两个演示身份、接受邀请、发送休息邀请、选择现在一起或稍后参与、完成活动和退出花园。演示数据仅存在该浏览器，**不能跨设备同步**。

配置 Supabase 后，花园改为真实联网模式。双方通过各自浏览器的匿名身份加入同一花园；服务端校验邀请 token、到期时间、人数和成员身份。花园只有两个成员和一株植物；双方各自确认完成活动后，服务端记录共同贡献。60 秒休息邀请的“现在一起”有效期为 10 分钟；“稍后参与”不表示发起者在线等待。参与者开始计时后，服务端要求满 60 秒才能接受这次邀请的贡献。贡献按用户和 activity session 唯一约束去重，数据库事务避免并发覆盖。花园同步昵称、成员、休息邀请状态和必要的共同贡献；个人关注部位、提醒日程和活动笔记只保存在本地。

### 启用真实花园

1. 创建 Supabase 项目，在 Authentication → Providers 启用 Anonymous Sign-Ins。
2. 在 Supabase SQL Editor 执行 [`supabase/migrations/001_garden.sql`](supabase/migrations/001_garden.sql)。迁移建立表、成员读取规则和服务端 RPC。
3. 复制 `.env.example` 为 `.env.local`，填入项目 URL 和 **publishable/anon key**，不要填写 service role key，也不要提交真实密钥。
4. 重新启动应用。两位使用者分别在自己的浏览器打开可访问的应用地址。将应用部署到双方都能访问的 HTTPS 域名后，可直接分享邀请链接；仅在自己电脑可访问的 `127.0.0.1` 链接不能发给另一台设备使用。

当前使用匿名身份，不提供跨设备账号迁移。清除某位用户浏览器的站点数据后，会失去该身份和原花园访问权；正式运营前应补充可恢复的登录方式。数据库中的个人完成由客户端提交用户确认，服务端防重复和校验成员，不验证真实身体活动。

### 数据与安全

- `src/lib/types.ts` 区分长期偏好、当前场景、陪伴 session、活动 session、提醒事件、完成奖励、花园成员、邀请和共同贡献。
- `src/lib/store.ts` 将旧版 `schemaVersion: 1` 数据迁移到 v2，保留活动记录、反馈、元气和灵宠；损坏的本地存储会回退到可打开的初始状态。
- `src/lib/garden.ts` 是明确标注的单浏览器演示；`src/lib/gardenRemote.ts` 和 `supabase/migrations/001_garden.sql` 是真实联网实现。
- 数据库存取启用 RLS。只有成员能读取花园、成员、贡献和休息邀请。邀请 token 不能直接通过表查询；接受、退出和贡献都经服务端函数检查。
- `supabase/tests/` 包含 PostgreSQL 权限与去重冒烟测试。它使用临时本地数据库，不需要真实 Supabase 密钥。

旧版及新版个人记录仍在当前浏览器的 `localStorage`（键 `moyu-wellness-v1`）。清除浏览器数据、隐私窗口结束或更换设备会丢失个人记录。存储不可用时应用仍能打开，但会提示无法保存。

## 网页提醒边界

站内提醒依赖页面保持运行。切到后台时浏览器可能节流计时器，设备休眠或关闭页面后不能保证按时提醒；重新打开页面会根据保存的时间检查并显示到期提醒。浏览器通知仅在用户于设置中主动点击授权后尝试，授权也不保证页面关闭后继续触发。应用没有系统级后台服务或真实久坐检测。

## 内容状态

沿用的 12 项轻活动仍标记为 `demo-pending-review`，正式公开发布前需要逐项审校步骤和注意事项。节气文案是文化主题演示，不宣称精确历法计算；元气签只供娱乐，不预测运势。灵宠和植物是临时原创图形。主题包只供预览，未接入支付。

## 第二阶段：场景感知与微活动

当前是 Next.js Web 应用，不是 PWA，也没有可信的久坐传感器。陪伴模式按用户设定的 45–60 分钟等间隔和页面运行状态发出提醒。提醒中可直接确认最近场景、主观需求、时间与空间；可选择现在活动、15 分钟后、今天先跳过或暂停。位置权限不会被请求。网页后台、休眠和关闭页面的限制见上文。

场景包含图书馆/自习室、办公室/工位、家中/宿舍、教室/会议室、公共交通、户外/公园与其他。空间分为保持坐姿、可站立、有宽敞空间和可以外出。主观需求覆盖颈、肩、上背、腰背、眼、手、髋、腿脚和全身，既可在首次设置中选择长期关注，也可在首页或提醒中快速修改当下需要。这些标签不构成诊断。

### 动作与证据结构

- `src/lib/types.ts` 中的 `Activity.meta` 保存英文名、类别、L1/L2/L3、目标部位、姿势、空间、噪声、器械、时长与重复参数、常见错误、预期作用、安全提示、限制、证据来源 ID、证据等级、审核状态、文化标签、动画资源及启用状态。L 级表示动作与空间幅度，**不是医学运动强度等级**。
- `src/lib/microActivities.ts` 包含下巴微收和肩胛轻夹两张 30 秒教学卡。另有 22 个待审核动作名称，`status: needs-review`，没有编造步骤，**不会进入自动推荐**。原有 12 项轻休息内容在 `src/lib/activities.ts` 保留，补入 D 级产品体验元数据，仍标为待审核。
- `src/lib/evidenceSources.ts` 独立记录机构、标题、网址、适用动作、来源支持的**具体结论**及审核状态。WHO 指南只作为久坐与活动的公共卫生背景，不是 30 秒具体动作疗效证据；NHS 资料支持两张卡的动作方向，但产品设定的时长与次数未被这些资料直接验证。没有复制来源的图文或视频。
- `src/lib/recommend.ts` 先过滤禁用、用户标为不适或不舒服、场景、空间、行动条件、时间、静音和器械需求，再按当下身体需求、来源核对状态、最近使用、完成比例、喜欢记录、长期场景和文化主题排序。最后一项仅作低权重点缀。无匹配时展示空状态。

教学卡用文字、当前步骤与计时进度提供引导，没有未经核对的姿势动画。支持暂停、继续、退出、换动作、“不舒服”立即停止与完成反馈。已核对动作和花园 60 秒邀请需计时结束才能确认奖励；同一 session 不会重复领奖或贡献。设置页可重新启用曾标为不适的动作。虚拟花园继续复用既有本地演示与 Supabase 接入，不共享身体需求标签。

**上线前仍需**由合适的健康内容专业人员审校两张卡的具体剂量、措辞与适用范围，逐项审核其余计划动作，并为准确姿势示意制作、核对原创素材。没有真实 Supabase 配置时，跨设备花园仍未实测。
