# 半日闲：庭园微运动游戏

把现实里的一次短休息，变成小竹在山居中的一次相遇。地图是主要操作界面，动作、抽签与植物不再并排成为功能卡片。

## 地点与原有功能

- 松风亭：离屏看远，沿用原有短休息引导。
- 舒展堂：根据时间、姿势、场景和设备筛选动作，保留步骤、暂停、继续和明确完成确认。
- 听溪桥：根据能否离座给出休息建议；进入地点不改变能否离座的已有选择。
- 百草圃：紫苏种植、照料和标本收集。
- 拾光轩：保留原有每日一签、揭签仪式和历史记录。

一次明确确认的运动，或主动记入手记的短休息，会让小圃多开一朵花。每三次休息推进山居篇章，共四个阶段；花朵最多展示九朵。这里只记录用户确认，不声称检测了真实动作。没有倒退、排行榜或连续签到惩罚。

世界中的进度直接由现有 sessions 和 restJournal.notes 推导，不建立第二套存档。今日次数按所选庭园城市的日期统计。暂停的活动可返回地图，继续入口保留；到期提醒和保存错误会在地图浮现。弹层支持焦点约束、键盘退出和还原焦点，开启时地图和导航不可交互。

## 美术与实现边界

地图使用用户提供的参考图（public/art/garden-world.png），不是重新生成的原创场景。小竹沿用现有 SVG，新增花朵也是 SVG。无外部图库、无虚构使用数据。角色是在地点之间插值移动，目前没有道路寻路、碰撞或摄像头动作识别。

设计流程抽取 Accent ladder（seed 155787494），保留参考图的青绿、宣纸色与宋体方向。用户要求游戏画卷，因此保留游戏标题字号与纸本色，不套用后台仪表盘标题及纯白底的限制。地图与角色的小投影表示悬浮交互标记；对话框已去除重阴影。

## 验证

- 64 个单元测试通过，包含城市日期跨日的庭园进度和存档恢复。
- 4 条新增端到端场景在生产构建通过：桌面和手机分别验证计时暂停、返回、继续、完成开花、刷新恢复，以及看远、抽签、草木册。
- TypeScript、源码 ESLint、Next.js 生产构建通过。全仓库 lint 会另外扫描到现有 `.pitch-build/build.mjs` 的 `console` 未定义错误；本次未修改该文件。
- 真实浏览器检查 1440、768、390 三种宽度，测量无 FAIL；保留与纸本游戏方向相关的颜色、标题字号及次要标签字号提示。

旧的 rest.spec.ts 为原首页布局编写，尚未整体迁移为地图入口；本次针对新主流程新增 garden.spec.ts，未宣称旧端到端套件全部通过。

## 视觉复核

地图是第一眼主体；主要行动在小竹对话框中，桌面侧边为山居状态，手机收为顶部。看过桌面、平板、手机的首屏及整页截图，标题无折行，页面无横向溢出。自评：设计 6.5、可用性 8、创意 7.5、内容 8，加权 7.3/10。主要限制是单张背景下的地点切换；后续若要更接近完整独立游戏，需要拆分景物图层、制作统一角色动画与可走路径。当前已可完整演示休息与庭园反馈的交互循环。
