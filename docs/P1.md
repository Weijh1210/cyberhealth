## 后端方案、成本与阻塞
沿用 Supabase PostgreSQL / Auth / RLS，邮箱 OTP 自愿登录，不改变游客体验。云端活动使用 `(user_id,event_id)` 唯一键，只导入用户同意的真实完成记录；偏好用乐观版本号检测冲突，让用户明确选本地或云端。不同账号在本机使用不同存储键，退出恢复游客仓库。导入失败不清除本地数据。

[官方价格](https://supabase.com/pricing)（本轮核对）：Free $0/月，500 MB 数据库、50k MAU、5 GB egress；不活跃 1 周会暂停。Pro 从 $25/月起，可有计算/流量等额外费用。本轮不开通付费服务。邮箱投递的测试限制与正式 SMTP 配置需在测试项目验证，不把 SDK 请求成功当作实际送达。

阻塞：没有测试项目环境变量、没有批准执行的数据库迁移。允许准备代码与 SQL 草案，**不执行远程迁移、不创建服务、不声称两真实账号验收通过**。用户需配置 `.env.local`（仅 publishable/anon key，不用 service role）、启用邮箱 OTP、按审核后的迁移步骤建立测试数据库，再联调。

## 数据库与权限设计

`001` 为既有花园；`002_personal_sync.sql` 新增个人 settings（user_id、revision、preferences）和 events（user_id、kind、event_id 唯一、不可变 payload），RLS 仅本人正式账号可读，禁止直接写，RPC 校验身份与偏好版本。同步只包含终态活动及用户同意的反馈/提醒/曝光，不包含好友的身体关注信息。

`003_garden_p1.sql` 增加 owner_id、私有奖励/社交限频账本，保留旧身份、成员和已得点数。入口均核验正式账号，旧事务函数变为不可直接调用的 helper。加入/奖励/退出用事务锁与唯一键保证约束。链接 token 由 pgcrypto 生成；上限两人，7 天到期；链接生成 60 秒间隔、每日 10 条。60 秒邀请需 10 分钟内回应，30 分钟间隔、每日 3 次；接受稍后可异步参与。露水每人每日 5 份（北京时间日界），事件终态、白名单和时间校验；单一活动 ID 全局只奖励一次，退出再加入不能重新领取。好友快照只有昵称/贡献摘要，不提供私人活动 payload。退出后旧链接撤销、权限立即失效；仍有成员时维护者转移且成长保留。

服务端依据用户提交的确认与时间信息，不证明实际身体活动。当前花园采用 15 秒轮询，无 Realtime 或后台推送服务。所有 SQL 仍为待确认草案，未访问生产或远程执行。
